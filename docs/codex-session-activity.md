# Codex 会话操作与写入检测

## 依据

现有存储代码使用 `state_5.sqlite` 的 `threads.id` 定位会话，`rollout_path` 指向当前文件。分页会话续写时路径可能变化，不能只检查列表此前显示的存根。删除原本已支持 App 运行时操作；其余操作的进程级拒绝没有崩溃证据，实际需要防范的是目标记录变化和 Desktop 私有 JSON 被内存缓存覆盖。

## 行为

`codex_activity.rs` 对操作已定位的文件和按主键查询的线程行取样，间隔 350 ms 再比较，并在准备完成、首次写入前再次检查。文件取样包含长度、修改时间和末尾最多 8 KiB 的哈希，避免反复读取大历史文件。数据库不复制、不比较整个数据库或 WAL 的时间，也不为活跃检查扫描其他会话。原操作为校验历史引用而进行的目录扫描仍保留。

检测到变化返回 `SESSION_BUSY`，桌面与 Web UI 统一弹窗；批量结果中的逐条错误也会触发。CLI 保留同一拒绝信息。新建目标不会因为另一个会话写入而被阻止。分页会话通过官方 `thread/fork` 复制时继续交给官方接口处理。

覆盖范围为 Codex 删除、移动工作目录、归档切换、恢复/导入目标、本地复制与回溯分支、provider 本地切换、分支回滚/追加、孤儿线程清理及作为转换来源的读取。数据库事务、原有完整文件指纹与补偿处理继续保留。App 启动或运行只会推迟其私有全局 JSON 的更新，不撤销已完成的 Core 操作。

## 边界与验证

350 ms 无变化只是未观察到写入，不能识别正在等待工具/网络的生成，也不能锁住外部进程未来的追加。该检测降低竞态概率，不宣称提供跨 App 的互斥锁或崩溃保证。消息编辑仍沿用原有的读取哈希、写入前比对及原子替换校验。

合成 fixture 验证目标文件追加会被拒绝、线程改指向或续写文件变化可被发现、其他会话写入不会误拦截，并验证 App 运行期间空闲会话仍可删除和移动。恢复、导入、转换、provider 切换及中途启动 App 的回归测试验证 Core 操作完成且私有 JSON 原样保留；原有真实并发修改拒绝与回滚用例继续运行。不使用真实用户会话测试删除或移动。
