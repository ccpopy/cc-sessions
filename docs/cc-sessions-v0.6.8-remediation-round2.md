# v0.6.8 第二轮性能与可靠性整改

日期：2026-09-16。接续 [第一轮整改](cc-sessions-v0.6.8-remediation.md)，本次范围为用户确认的现有功能优化，不包含 Handoff、版本升级或发布。

## 验收范围与实现

| 项目 | 本次行为 | 验证方式 |
| --- | --- | --- |
| 按数据目录隔离写锁 | 规范化实际路径作为锁标识；目录别名、Windows 大小写及长路径格式共用锁；尚未创建的普通目录在创建前后保持同一标识。进程内与进程间锁都按固定顺序获取，多目录去重，整个等待过程限时 30 秒 | 同目录阻塞、不同目录并行、子进程争锁、超时后释放、反向多目录请求及路径别名测试 |
| 写入凭据 | 原子写入器随写入计算摘要，在提交成功时登记实际写出内容；提交后的清理错误仍保留凭据。回滚不再事后读取目标来猜测写入归属；拒绝将外部更新后的指纹作为本次基线 | 写后外部更新、基线漂移、一次回调内多次写入、先成功后冲突、已提交后错误、无凭据写入测试 |
| 磁盘补偿快照 | 原字节流式写入同目录独占临时文件并同步，保留内容摘要与权限；内存保存路径和摘要。恢复时流式读取并验证快照和目标；提交成功清理，冲突或失败报告保留位置 | 快照创建计数、成功清理、恢复后清理、快照损坏、目标变化、无凭据更新与清理冲突测试 |
| 扫描复用与局部复核 | 诊断共享一次请求内的线程、索引和已有 rollout 身份清单。可见性修复及官方分页派生的复核只查询相关线程，并检查刚写入索引行的字节范围；批次保留已选 rollout 路径 | 诊断扫描计数、三条会话修复计数、索引行与线程被外部修改后的复核，以及既有分页存根/延续文件回归 |

保持原有 Tauri、CLI、WebUI 业务入口。编辑、移动、转换、分支、归档、删除、导入和还原使用相应源目录锁；索引重建、线程表重建以及 Claude 历史/可见性修复也与相同目录的操作互斥。转换与编辑涉及多个共享目录时一次排序加锁。导入、还原先检查输入，再按每条实际目标的数据目录持锁执行，保留逐条失败报告。

Family JSON 保存改为复用统一原子写入器，使用 64 KiB 缓冲，避免逐个 JSON 标点触发文件写入。Core 索引修复与 Desktop 项目归属的边界保持不变，没有新增依据 rollout cwd 创建项目的行为。

## 工作量证据

以下为人工 fixture 的结构性计数，不是总磁盘 I/O、RSS 或真实机器加速比例：

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 一次诊断 | 线程表与索引分别扫描 2 次 | 分别 1 次，同一份结果用于差集与 provider 计划 |
| 3 条会话的可见性修复 | 计划加逐条复核，线程表与索引分别扫描 4 次 | 各 1 次计划扫描；3 次按 ID 查询和 3 次对应索引行检查 |
| 登记新写入的 1 MiB 文件补偿 | 写完后再读目标以建立“本次写入”指纹 | 登记阶段不读取新目标；摘要由写入流产生 |
| 1 MiB 旧文件的快照 capture | 1 MiB 原字节常驻内存；读取及哈希各 2 MiB | 1 MiB 快照落盘；读取及哈希仍各 2 MiB，复制内存有界 |

`CC_SESSIONS_PROFILE` 新增 `snapshot_bytes`、`thread_table_scans`、`index_scans`、`local_thread_queries`、`local_index_checks`。这些字段只计已插桩的阶段。索引重写、原子提交前内容核对、补偿和清理的读取仍然存在；不能将“1 次计划扫描”解释为整个批次只读取一次索引文件。

## 剩余边界与下一步

1. **磁盘快照尚不具备崩溃自动恢复能力。** 操作计划、写入凭据和事务状态仍在内存中；还没有持久化 op_id、与 SQLite 同事务的提交标记或重启恢复器。后续可继续实现，并以强制终止/重启测试验证。保留快照不能等同于跨存储事务。
2. **本工具的锁只协调遵守同一协议的 CC Sessions 实例。** 原生 Codex、Claude 等不使用此锁；POSIX 最终核对与 rename 的窗口、旧文件描述符继续写入仍需官方接口或逐操作协调。旧版 CC Sessions 的全局锁与本版目录锁不互通；更新后应重新启动各入口。Windows 与 WSL/Linux 实例也不共享同一操作系统锁。
3. **快照把内存成本转移到磁盘。** 操作期间需要容纳原文件快照，多个补偿步骤会累计占用空间；创建失败会在修改目标前返回错误。快照和清理所需 I/O 未被取消，没有承诺所有大文件操作总耗时都下降。
4. **扫描优化仍有可继续推进的范围。** 本次复用只在请求内有效；没有持久化摘要缓存、按追加内容解析或跨页面缓存。目标正文和 family 的实时读取仍保留；检查已有目标分支时仍可能全量读取索引，索引逐项改写也仍有线性成本。
5. **平台验证尚未齐全。** 当前执行环境为 Windows。Unix 权限、flock 和符号链接测试已保留/补充，但未在 Linux/macOS 运行；第一轮已确认本地 WSL 缺少 Rust 工具链。权限保留使用标准文件权限接口，未承诺保存完整 ACL。跨平台结论需对应 CI 或系统实测。
6. **其余独立工作仍可继续。** 持久化恢复完成后可接退出/更新屏障；工具/推理及其他来源的流式导出、导入/导出/校验的取消能力也仍是后续范围。

本次不更改版本、不创建提交、不推送或发布；原始审查文档和 review-pack 保持原样。
